Fix `orientation` on a foldable iPhone simulator (iPhone Duo) in a scoped simulator set. It no longer refuses with `unsupported-device-scope`: the fold helper already reaches a scoped set, so the rotation is dispatched through it and succeeds only when the lit panel shows the requested orientation, otherwise failing with `orientation-unverified-scoped-set`. Measured on iPhone Duo, the lit panel usually reads the orientation-picker value plus a fixed per-panel offset (0 degrees on the outer panel, +90 degrees on the inner panel), and the picker value survives a fold; a panel whose foreground app cannot show that orientation keeps its previous one instead. Each dispatch is therefore the target minus the lit panel's offset, taken from the measured value at first and then recalibrated from the last dispatch and a fresh reading of the same panel, so the first command lands. A reading that has not moved since the last dispatch teaches nothing and is not followed by another dispatch, so a panel that cannot show the target fails after one dispatch. The fold helper also maps `portrait-upside-down` to the picker's `pud` wire spelling, which the inner panel needs to reach landscape-left; a user target of `portrait-upside-down` stays refused.
